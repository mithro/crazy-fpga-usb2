# P5 Virtual UTMI PHY + LUNA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** LUNA's unmodified `USBDevice` enumerating over the soft PHY: a `SoftUTMIPHY` that looks like a UTMI transceiver to LUNA (data, op-modes, chirp, line state), a `SoftPHYUSBDevice` subclass that keeps LUNA in high-speed mode, a Python high-speed host model that enumerates the device at the bit level in simulation (at 0 and ±500 ppm), and a `device-test` applet in which a small gateware host ("host-lite") enumerates a LUNA device through two soft PHYs inside one NeTV2, with counters over the UART, run on rpi5-netv2. The two-board HDMI variant is documented and ready but blocked on cabling, as in P4.

**Architecture:** `SoftUTMIPHY` wraps the P2 `RxPath` and P3 `TxPath` and adds the UTMI control plane: `op_mode` (NORMAL → encoder; NON_DRIVING → output enable forced off; CHIRP/raw → constant K driven directly at the 120 MHz line-bit level, bypassing SYNC/stuffing/NRZI), `term_select`/`xcvr_select` (recorded, no electrical effect on the HDMI/internal platforms), `line_state` (squelch-derived in HS: SE0 while the CDR sees no activity, J/K from the differential level while a packet is present), `session_end = 0`, `vbus_valid = 1`. `LineStateSynthesiser` (spec §4.5) plays the host half of reset-and-chirp for platforms without full-speed levels: SE0 from power-up until LUNA's device chirp ends, then three K/J pairs; it re-arms on **every** device chirp so LUNA recovers after any 3 ms idle or peer reset. `SoftPHYUSBDevice(USBDevice)` sets `always_fs = False` and `data_clock = 60e6` after `super().__init__()` (both are read only in `elaborate`). `sim/host.py` builds tokens/data/handshakes (CRC5/CRC16), drives sample words into a PHY and decodes the PHY's line output, and scripts enumeration. `HostLite` is a ROM-scripted packet player/checker (constant token, SETUP-data and ACK packets; expected responses compared byte-for-byte; SOF every 125 µs with a live CRC5) behind its own `SoftUTMIPHY`; `device-test` connects host-lite PHY ↔ device PHY with two `SampleExpander`/`AsyncResampler` wires.

**Tech Stack:** Amaranth 0.5.9, LUNA (`mithro/luna@crazy-fpga-usb2`, Greg Davill's fork), Vivado 2025.2, rpi5-netv2. Branch `p5-utmi-luna` from `main` after PR #4.

Rules: native Amaranth only; no LUNA source changes (subclass / wrap / monkeypatch-in-tests only); `uv run pytest -q` green before every commit; hardware loads announced and rows added to the rpi5 coordination file, edited only by their own timestamp.

## Facts from LUNA that the design depends on (verified in the pinned checkout)

- `USBDevice.__init__(bus=...)`: an object without `dir`/`d_n` attributes is used as the UTMI bus directly and sets `always_fs = True`, `data_clock = 12e6`; both are read only in `elaborate` (`USBTokenDetector(fs_only=self.always_fs)`, `USBInterpacketTimer(domain_clock=self.data_clock, ...)`), so a subclass can override them after `super().__init__()`.
- The device drives `utmi.op_mode`, `xcvr_select`, `term_select`, `dp_pulldown`/`dm_pulldown`(=0), `tx_data/valid`; it reads `rx_data/valid/active/error`, `line_state`, `session_end` (`vbus_connected = ~session_end`), `tx_ready`.
- `USBResetSequencer` (60 MHz `usb` domain; constants are class attributes `_CYCLES_*`): LS_FS_NON_RESET → SE0 for 5 µs → `bus_reset`, START_HS_DETECTION (`current_speed = HIGH`, `op_mode = CHIRP (2)`, `term_select = 1`) → DEVICE_CHIRP: `tx.valid = 1, tx.data = 0` for 2 ms → AWAIT_HOST_K: needs `line_state == K (0b10)` held 2.5 µs, then J (0b01) 2.5 µs, three pairs, each wait bounded by a 2.5 ms timer (`IS_LOW_OR_FULL_SPEED` on timeout) → IS_HIGH_SPEED (`op_mode = NORMAL`, `term_select = 0`) → HS_NON_RESET. In HS_NON_RESET, `line_state == SE0 (squelch)` for 3 ms → FS, DETECT_HS_SUSPEND: after 200 µs `line_state == J` → SUSPENDED else `bus_reset` → START_HS_DETECTION (re-chirp). Consequence: a host must keep traffic (SOFs) flowing at least every 3 ms or the device resets; that is real-USB behaviour and the host-lite sends SOFs every 125 µs.
- Line state encodings: SE0 = 0b00, FS/HS K = 0b10, FS/HS J = 0b01.
- LUNA has no host-side gateware; `luna.gateware.usb.usb2.packet` has `USBTokenDetector`, `USBDataPacketReceiver/Generator`, `USBHandshakeDetector/Generator`, `USBDataPacketCRC` (device side) which `HostLite` does not need beyond constants.

### Task 2: Line state (`usb2soft/phy/linestate.py`)

`HSLineState(cdr_domain="rx_cdr", usb_domain="usb")`: inputs `activity` (CDR, 120 MHz), `level` (last sample of the word, 120 MHz); output `line_state[2]` in usb domain via a 2-FF synchroniser of a 120 MHz-registered pair: `00` when `~activity`, `01` (J) when active and level 1, `10` (K) when active and level 0. Also expose `squelch` (= ~activity synchronised) for the synthesiser.

`LineStateSynthesiser(*, se0_cycles, gap_cycles, hold_cycles, pairs=3, domain="usb")`: inputs `op_mode[2]`, `tx_valid`, `squelch_line_state[2]`; output `line_state[2]`, `active` (synthesiser owns the line state), `armed_count` (statistics). Behaviour: power-up → SE0 for `se0_cycles` (must exceed LUNA's 5 µs = 300 cycles; default 600) → hand over to squelch. Whenever `op_mode == 2` and `tx_valid` falls (device chirp end): wait `gap_cycles` (default 60 = 1 µs) then K for `hold_cycles`, J for `hold_cycles`, ×`pairs` (default hold 300 cycles = 5 µs, i.e. all six levels in 30 µs ≪ 2.5 ms), then squelch again. A new device chirp while playing restarts the sequence.

- [ ] Tests (`tests/test_linestate.py`): (a) `HSLineState`: activity 0 → 00; activity with level 1 → 01; level 0 → 10; drops to 00 within 4 usb cycles of activity ending. (b) synthesiser: with small cycle parameters, the sequence timing is exact (SE0 length, gap, K/J durations, then squelch pass-through), and a second chirp restarts the sequence (re-arm). (c) a chirp *during* SE0 (LUNA chirps while our SE0 is still running if `se0_cycles` is long) also produces the K/J sequence afterwards.
- [ ] Implement; run; commit `phy: HS line state and re-armable chirp synthesiser`.

### Task 3: `SoftUTMIPHY` (`usb2soft/phy/utmi.py`)

Signals (all LUNA names): `tx_data[8]`, `tx_valid`, `tx_ready`, `rx_data[8]`, `rx_valid`, `rx_active`, `rx_error`, `line_state[2]`, `vbus_valid` (const 1), `session_end` (const 0), `session_valid` (1), `xcvr_select[2]`, `term_select`, `op_mode[2]`, `suspend`, `dp_pulldown`, `dm_pulldown`, `id_pullup`, `chrg_vbus`, `dischrg_vbus`, `use_external_vbus_indicator`, `host_disconnect` (0), `id_digital` (0); plus `line[4]`, `oe[4]` (tx domain) and `samples[16]` (cdr domain) for the wire.

Behaviour:
- `op_mode == NORMAL (0)`: `tx_*` → `TxPath`; `line/oe` from the encoder.
- `op_mode == NON_DRIVING (1)`: `oe = 0`, `tx_ready = 0`.
- `op_mode == 2` (chirp / raw): `oe = 1111`, `line = 0000` (K) while `tx_valid` (synchronised into the tx domain with an `FFSynchronizer`); the encoder is fed nothing; `tx_ready = 1`.
- `op_mode == 3`: treated as NORMAL (LUNA never uses it).
- `line_state` from `LineStateSynthesiser` when present (`active`), else `HSLineState`.
- `rx_*` straight from `RxPath`; during our own transmission the loopback wires do not echo, so no half-duplex masking is needed (documented; a real bus would need `rx_active` masking while `oe`).

- [ ] Tests (`tests/test_soft_utmi.py`): (a) NORMAL: a byte packet through `tx_*` comes out on `line/oe` and decodes with `usbhs.reference_decode` (reuse the P3 harness); (b) op_mode 2 with `tx_valid=1` drives `oe=0xF, line=0x0` continuously and returns to idle (`oe=0`) within 3 tx cycles of `tx_valid` falling; (c) NON_DRIVING keeps `oe=0` even with `tx_valid`; (d) `line_state` is SE0 while idle and non-SE0 while a packet is being received; (e) synthesiser precedence.
- [ ] Implement; run; commit `phy: SoftUTMIPHY (UTMI face of the soft PHY)`.

### Task 6: `HostLite` gateware (`usb2soft/host/hostlite.py`)

Script (constants computed in Python at elaboration with `usb_crc`): the same sequence as Task 5 at address 0 then address 5, then a steady-state loop `GET_DESCRIPTOR @5 → IN → ACK → OUT ZLP → ACK`. Each ROM step: `tx_bytes` (up to 11 bytes: SETUP token 3 + DATA0 8 + CRC16 2 = 13; make the ROM entry 16 bytes with a length), `expect` (`ACK` | `DATA1 with exact bytes` | `NAK allowed → retry`), `timeout` (736 bit times = 92 usb cycles + PHY latency margin → 256 cycles). SOF: independent timer, 7500 usb cycles (125 µs), inserted between steps when `~busy`, frame counter 11 bits + hardware CRC5 (11-bit LFSR, ~10 LUTs). Counters: `cycles` (steady-state loops completed), `ok_replies`, `bad_replies`, `timeouts`, `nak`; `state` for the console. UTMI side: `tx_data/valid/ready`, `rx_data/valid/active/error` toward the host PHY; the host PHY runs `op_mode = NORMAL`, no synthesiser (the host PHY only needs data).

## Amendments after the plan review (2026-09-07)

The review (subagent, against the pinned LUNA source) approved the LUNA facts and flagged these;
all are binding on the tasks above:

- **Scaled constants**: every patched `_CYCLES_*` must be ≤ the patched `_CYCLES_3_MILLISECONDS`
  (it sizes the sequencer's `timer` and `line_state_time`); in particular `_CYCLES_200_MICROSECONDS`
  is patched to 600 (`tests/luna_harness.py:SCALED`). Monkeypatch before `Simulator(dut)`.
- **`device.connect` must be driven high** in every harness and applet (`device.py:247,391`);
  `term_select` is only meaningful then (1 during chirp, 0 after `IS_HIGH_SPEED`).
- **Synthesiser arming**: LUNA answers packets while `op_mode` is still 2 (from START_HS_DETECTION
  to IS_HIGH_SPEED), so a `tx_valid` falling edge alone is not a chirp end. `LineStateSynthesiser`
  has `min_chirp_cycles` (default 60 000 = 1 ms; the device chirp is 2 ms) and only arms on a K
  burst at least that long. Host-lite starts its script after a power-up hold-off (≥ 3 ms) and
  restarts from step 0 after N consecutive timeouts (a re-chirp resets the address to 0).
- **SOF placement**: only at transaction boundaries (an SOF between a SETUP token and its DATA0
  makes LUNA discard the SETUP, `request.py` READ_DATA). Same-transmitter gap between a token and
  its DATA ≥ 88 bit times (USB 2.0 §7.1.18.2); the host model and host-lite use 96.
- **Latency bound**: the device must start its response within 192 bit times (host timeout is
  736). Task 5 asserts ≤ 192 and reports the measured value (expected ≈ 90–100).
- **Observables**: `device.speed`, `device.reset_detected`, `device.suspended`, `device.sof_detected`,
  `utmi.op_mode/xcvr_select/term_select` (there is no `device.reset_sequencer` attribute).
- **`HSLineState` cannot express a static host chirp** (activity is edge-based, 8 UI), so the
  synthesiser is mandatory on every P5 platform; a level-based line state for set-ups 2/3 is future
  work and the spec §4.5 wording is amended accordingly. The device's static 2 ms K is invisible
  to the host PHY's decoder (needs 8 decoded zeros), so no masking is required.
- **Async mode** (Task 7): the host PHY's `cdr_domain` and `tx_domain` both run in `tx_async`,
  with two `AsyncResampler`s in opposite directions and the `set_clock_groups` constraint.
- **Host-lite**: ignore stray packets/`rx_error` when not waiting for a reply; add a `restarts`
  counter to the console line; module lives at `usb2soft/hostlite.py`.
- **Extra tests**: plain `USBDevice(bus=phy)` never leaves FS (guards the subclass rationale);
  a token to a wrong address gets no response.
- CRC worked examples in Task 1 were replaced by catalogue check values, residuals and LUNA
  cross-checks (stronger); Task 7 is split into applet+test and results commits.
